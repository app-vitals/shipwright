# Site Docs Freshness

> Per-page staleness tracking for the marketing site (`site/`), mirroring the repo-scoped `check-docs-freshness.ts` pattern at page granularity. Two artifacts exist today — `site/docs-source-map.json` and `plugins/shipwright/scripts/check-site-docs-freshness.ts` — but as of this writing neither is wired to a cron.

## Overview

`docs/consolidation.md`-style patrol crons work by pairing a cheap precheck script with a full-check command dispatched only when the precheck finds something worth doing. The repo-scoped `check-docs-freshness.ts` (wired as the `preCheck` for the `shipwright-docs-freshness` cron, see [`docs/architecture.md`](./architecture.md)) answers "has any repo changed source since its docs were last synced?" across every repo under `repos/`. The **site-docs-freshness** mechanism (SDR track) answers the same question at a finer grain: for the `site/` marketing pages specifically, which *individual page* has drifted from the source files it's documenting, tracked with its own last-synced anchor rather than one shared repo-wide anchor.

## The source map: `site/docs-source-map.json`

`site/docs-source-map.json` is the audit artifact that says what each marketing page is substantively derived from:

```json
{
  "<page>.mdx": ["<source path>", ...]
}
```

- Keys are bare `.mdx` filenames under `site/src/content/docs/` (no directory prefix).
- Values are repo-root-relative source paths that exist at HEAD — a `docs/*.md` file, a `plugins/shipwright/commands/*.md` file, or a directory (e.g. `plugins/shipwright/skills`) when a page draws from a whole directory rather than one file. Mappings are many-to-many by design.
- `_comment` documents the file's purpose; `_notes` holds an explanation for any page mapped to an empty source array (a page with no repo-doc source) — currently empty, since every page on the site today traces back to at least one `docs/` or plugin source.

**Who builds and maintains it:** it's a manually-curated audit, not generated by a build script. There's no `docs-source-map`-builder in `scripts/` — a human (or an agent doing the SDR-1-style audit) adds/updates entries by hand when a site page's content changes. Correctness is enforced structurally by `scripts/docs-source-map.unit.test.ts`, which runs under the root `bun test` (it lives at the repo root rather than under `site/` because `bunfig.toml` excludes `site/**` from the root test scan) and checks:

- the map is valid JSON and covers every current `.mdx` page under `site/src/content/docs/`
- it has no stale entries for pages that no longer exist
- every entry is an array of strings, and every listed source path actually exists on disk
- an empty source array is only valid when paired with a `_notes` explanation

Adding a new site page or deleting an old one without updating the map fails this test — that's the enforcement mechanism, not a separate lint rule.

## The precheck: `check-site-docs-freshness.ts`

`plugins/shipwright/scripts/check-site-docs-freshness.ts` mirrors `check-docs-freshness.ts`'s anchor-based pattern (`getCommitsSince` / `getChangedFilesSince` against a last-synced SHA, exit 0/1 contract) but is **page-scoped instead of repo-scoped**: it operates on exactly one repo (cwd, this repo) and evaluates each page in the source map independently, against its own anchor, rather than one shared repo-wide anchor.

Anchors are read from `state/site-docs-last-synced.json` — `{ "<page>.mdx": { "sha": "...", "timestamp": "..." } }` — one entry per page. This file does not exist yet in this repo (no page has ever completed a sync), so today every page falls into the "first run" case below.

For each page in the source map:

| Case | Result |
|---|---|
| Page maps to zero source paths (paired with a `_notes` entry) | Never qualifies — short-circuited before any git call, since an empty pathspec to `git log`/`git diff` means "no restriction" (matches everything), not "match nothing" |
| No anchor entry for the page yet | Qualifies (first run — always worth checking) |
| Anchor exists, no commits touch the page's mapped source paths since that SHA | Does not qualify |
| Anchor exists, commits touch a mapped source path | Qualifies, changed-file summary recorded |
| A page's own git call fails | Treated as qualifying (permissive) — isolated to that page, does not block or suppress findings for other pages |

**Exit-code contract:**

- **Exit 0** + page-scoped summary on stdout — at least one page has source changes worth checking. Output lists each qualifying page, either with its changed files or (no-anchor case) `"{page}: no sync anchor found — run full docs check"`.
- **Exit 1** + no output — nothing to do for any page.

Unit-tested via `plugins/shipwright/scripts/check-site-docs-freshness.unit.test.ts`, which injects stub dependencies (no real git/filesystem I/O) and asserts the exit code for each case in the table above.

## Wiring status

**Not yet wired to a cron, as of 2026-09-14.** The script's own header says so directly: "Pre-check for a site-docs-freshness cron (not yet wired up — see SDR-4)." Confirmed against current `main`: no entry in `agent-types/coding/manifest.yaml`'s `crons` array references `check-site-docs-freshness.ts`, and no other cron/command in the repo invokes it — the script exists and is fully unit-tested, but nothing runs it outside of `bun test`.

For comparison, the repo-scoped `check-docs-freshness.ts` **is** wired today:

```yaml
- name: shipwright-docs-freshness
  schedule: "0 7 * * *"
  prompt: /shipwright:research-docs --auto
  preCheck: shipwright:check-docs-freshness.ts
  silent: true
  enabled: false
```

It's the `preCheck` for the `shipwright-docs-freshness` cron in `agent-types/coding/manifest.yaml` (see [`docs/agent-types.md`](./agent-types.md) for the manifest schema and the `preCheck` contract), driving `/shipwright:research-docs --auto`, and ships `enabled: false` per the new-system-crons-ship-disabled convention (see `plugins/shipwright/CLAUDE.md`).

Landing SDR-4 means adding the analogous cron entry for the page-scoped check — pointing at a command that consumes the precheck's per-page output — the same way `shipwright-docs-freshness` pairs with `check-docs-freshness.ts` today. Re-check this section against current `main` before relying on it; SDR-4 may have landed since this was written.
