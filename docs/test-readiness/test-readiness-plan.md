- **Net-new coverage gaps confirmed this cycle (Phase 3):** 2 real gaps, both single
  missing test *cases* inside already-existing, already-correctly-layered files — not
  missing files, not missing layers:
  1. `agent/src/check-review.ts`'s `isBundleComplete` `.catch(() => true)` fail-open
     consumer path (`check-review.ts:173-177`) has no test proving a *rejecting*
     `isBundleComplete` dependency still lets `getReviewCandidates` proceed
     (fail-open-as-designed) rather than excluding the PR. `check-review.unit.test.ts:631-664`
     only covers the resolve-`true`/resolve-`false` cases, never a rejection.
  2. `agent/src/agent-author-allowlist-ref.ts`'s `hasSynced()` never-synced state has no
     dedicated unit test proving `check-review.ts`'s `isAuthorAllowed` default closure
     treats "never synced" and "synced-to-empty" as intentionally equivalent (both
     fail-open/unfiltered). The existing test
     (`check-review.unit.test.ts:678-683`) calls `agentAuthorAllowlistRef.set([])` first,
     which flips `hasSynced()` to `true` — so it only proves the synced-but-empty case.
     **Test-authoring wrinkle:** the shared `beforeEach` at
     `check-review.unit.test.ts:668-670` calls `.set([])` before every test in that
     `describe` block, defeating a literal "never synced" precondition for any test added
     inside it as-is. Properly testing this requires either a separate `describe` block
     that skips the shared `beforeEach`, or making the closure's ref dependency
     injectable (mirroring how `isBundleComplete`/`isAuthorAllowed` are already
     injectable) so the test can construct a fresh, never-`.set()` ref instance. Scoped
     below as "make the ref dependency injectable + add the test," not a one-line
     addition.
- **1 false-premise flagged gap, already resolved:** `admin/src/agents-api.ts`'s `POST
  /agents` unknown-type-400-before-any-write sequencing — landed 2026-07-24 in PR #2200,
  2 days before this cycle's inventory ran. No action needed.
- **Infra gap: none net-new.** Runner config, CI shape, Postgres containers, `Clock`
  helpers, recorded-fixture doubles, coverage gate all confirmed unchanged and correct.
