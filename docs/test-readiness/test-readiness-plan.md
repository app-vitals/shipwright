## 6. Open risks

- **T-080's scope depends on whether `scripts/hitl.ts` already exposes an injectable
  exec seam.** Phase 3 confirms the pure-planning helpers (`computeMissingClones`,
  `computeProvisionPlan`) are already injectable-I/O by design, mirroring the repo's
  established convention — but whether the *orchestration function* that sequences
  clone→seed→boot→poll already accepts an injected `gh`/process-exec dependency, or
  needs that seam added first, was not directly verified this pass (Phase 3 stopped at
  confirming the planning-helper unit tests exist). If the seam doesn't exist yet, T-080
  implicitly bundles "add the injection point" with "add the sequencing test" — the same
  shape as the prior cycle's T-078, which was an accepted single-task bundle because the
  test couldn't be correctly authored without the design change. Flagging so whoever
  picks up T-080 checks this first rather than assuming either shape.
- **Content-layer file count holding steady, still not independently full-audited.**
  This cycle's content-layer file count is unchanged at 35 `.content.test.ts` files —
  the delta landed as additive assertions on existing files
  (`plugins/shipwright/commands/dev-task.content.test.ts` and `review.content.test.ts`
  for RVG-1.1/BBE-1.2's companion doc changes), not new command/skill files. Phase 1
  still batch-classifies `plugins/shipwright/{commands,agents,skills}/*` as
  content-covered by established convention rather than confirming each file
  individually — the convention has held in every spot-check to date, so this isn't
  scored as a gap, but a full count-and-diff still hasn't happened in several cycles —
  worth doing the next time Phase 1/3 has spare scope.
- **The bash "shell" layer still needs a formal documentation decision.** Carried forward
  unchanged across several cycles now (first flagged 2026-07-31, re-verified present and
  unchanged this cycle — zero `.github/workflows/` changes since the `b693b880`
  baseline): `.github/workflows/lib/chart-tag-utils.sh` / `chart-drift-check.sh` and
  their `test-*.sh` siblings are genuinely tested code units that fall entirely outside
  the `bun test` runner and the five-suffix convention declared in root `CLAUDE.md`.
  Coverage itself is not in question (`test-check-chart-drift.sh` exists and passes) —
  the open question is purely whether a human wants to formally document this as a sixth
  layer in `CLAUDE.md`'s `## Test conventions` table and `docs/test-readiness/naming.md`,
  or confirm it should stay an unofficial exception. Not urgent; not blocking any task
  above.
- **Recorded-fixture coverage breadth** (~9 remaining `Http*Client` modules that could
  extend the `Recorded*Client` pattern) remains a Phase 2 design-level backlog item, not
  a migration-bucket verdict on any existing file. No task emitted this cycle since

- **`agent/src/piper-voice.ts` reclassification watch item** (unit today, integration
  once Piper synthesis lands) — still not landed as of this cycle; flagged so a future
