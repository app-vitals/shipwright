**CLAUDE.md layer-structure declaration:** the root CLAUDE.md's `## Test conventions` section declares five concrete layer names via filename suffix, used verbatim below instead of the rubric's generic unit/integration/smoke/E2E labels (unchanged since the 2026-07-21 inventory):

| Suffix | Layer | Covers |
|---|---|---|
| `*.unit.test.ts` | unit | pure logic, no I/O |
| `*.integration.test.ts` | integration | real dependency behavior via recorded fixtures / injected doubles |
| `*.smoke.test.ts` | smoke | HTTP route contracts — in-process `app.request()` (real `Bun.serve()` boot only when there's no Hono app-factory seam) |
| `*.spec.ts` / `*.e2e.ts` | e2e | real-browser Playwright (`site/` uses `*.spec.ts`; `admin/e2e/` uses `*.e2e.ts`) |
| `*.content.test.ts` | content | markdown/prompt-content assertions (commands, skills, agent prompts) — no I/O boundary, not one of the four canonical layers but a first-class fifth layer in this repo |

### 6. User journeys

Five top-level product journeys — unchanged in count this cycle, but journey #1 gained a scope note:

1. **dev-task → review → patch → merge/deploy pipeline** — the core product loop. Critical — this is the product. **New this cycle: `/shipwright:unblock` (30th command file) adds an explicit human-invoked triage sub-step** for `status: 'blocked'` tasks and `blocked: true` PRs — discover → infer originating phase → retry/redirect/abandon, one at a time, human-gated. 3. **Slack chat with an agent** — DM/mention → chat-svc queue → `agent/src/chat-poller.ts`'s poll/claim loop → Claude session → Slack reply. High. Unchanged this cycle (its `chat/src/routes/messages.ts` gained the shared `readJson` import swap, a no-op refactor from this journey's perspective).

5. **Local HITL dev-loop bootstrap** — `task hitl` → auto-clone missing repos → seed `agent-policy.md` → boot task-store + admin locally → poll for ready work → dispatch Claude Code. Medium. Unchanged this cycle.

No journey is browser-driven except #4 (plus #2's detail-page rendering step). #1, #3, and #5 are best proven by cross-service integration tests composing recorded fixtures / injected doubles rather than a literal Playwright E2E, since there is no UI for the pipeline or the HITL bootstrap itself — noted as "e2e / smoke-composed" or "integration-composed" in the summary table to flag that the canonical E2E *tooling* (browser automation) doesn't apply, but the *layer* (multi-step, multi-process state) still does.
