| Suffix | Layer | Covers |
|---|---|---|
| `*.unit.test.ts` | unit | pure logic, no I/O |
| `*.integration.test.ts` | integration | real dependency behavior via recorded fixtures / injected doubles |

Under the prior code, two concurrent claimers reading the same stale snapshot under READ COMMITTED could both pass the JS `if`, and the second writer would silently clobber the first's claim (a lost-update race). Now, Postgres — holding the row lock at execution time — is the sole arbiter: a losing writer's UPDATE matches 0 rows, Prisma throws `P2025`, and the catch block disambiguates `ConflictError` (row still exists, a concurrent claim now conflicts — the expected/desired outcome) from `NotFoundError` (row was deleted). `resetSkip()` also gained a companion UX fix: it now clears `blocked`/`blockedReason` in the same update, but only when the PR was auto-blocked by the skip-count mechanism specifically (`blockedReason` contains `"consecutive skips"`) — a block set by a different mechanism (e.g. the CI-failure-streak auto-block in `patch()`) is left untouched.
2. **`task-store/src/task-service.ts`'s `claim()`** — the same class of race is closed for tasks: the conditional UPDATE's `WHERE` clause gains an explicit `AND "claimedBy" IS NULL` (previously gated only on `status = 'pending'`).
3. **`agent/src/pr-state-reconciler.ts` — orphan-task reconciliation pass removed.** `listOrphanCandidateTasks`, `ghListOpenPrsForBranch`, and the `reconcileOrphanedTask`/`reconcileOrphanedTasks` functions are removed from both the `PrStateReconcilerDeps` interface and the reconciler body (a 547-line reduction in the paired unit-test file). The remaining `reconcilePrOpenTask`'s direct-path and branch-fallback heal logic, and their `startedAt`/BBR-1.1 headcount preconditions, are unchanged and re-documented in place to reflect that they're now the file's only two heal paths.
