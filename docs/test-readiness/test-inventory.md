## Stack profile

- **Language(s):** TypeScript (Bun runtime), plus Astro/Tailwind for the marketing site
- **Package manager:** Bun workspaces (`bun.lock`), 8-workspace monorepo (`lib`, `plugins/shipwright`, `metrics`, `agent`, `admin`, `task-store`, `chat`, `mcp-server`) plus non-workspace supporting surfaces (`site/`, `brand/`, `scripts/`, `charts/` Helm chart, `demo/`)
- **Primary framework(s):** Hono (all HTTP services: metrics, admin, task-store, chat), Prisma + Postgres (admin, task-store, chat), Zod/`@hono/zod-openapi` for schema validation, Astro (site), Playwright (site + admin + metrics E2E), Bun's built-in test runner throughout
- **Detected source roots:** `lib/`, `metrics/src/`, `agent/src/`, `admin/src/`, `task-store/src/`, `chat/src/`, `mcp-server/src/`, `plugins/shipwright/{commands,agents,skills,scripts,references}/`, `scripts/`, `brand/`, `site/src/`

**CLAUDE.md layer-structure declaration:** the root CLAUDE.md's `## Test conventions` section declares five concrete layer names via filename suffix, used verbatim below instead of the rubric's generic unit/integration/smoke/E2E labels (unchanged since the 2026-07-21 inventory):

| Suffix | Layer | Covers |
|---|---|---|
| `*.unit.test.ts` | unit | pure logic, no I/O |
| `*.integration.test.ts` | integration | real dependency behavior via recorded fixtures / injected doubles |
| `*.smoke.test.ts` | smoke | HTTP route contracts — in-process `app.request()` (real `Bun.serve()` boot only when there's no Hono app-factory seam) |
| `*.spec.ts` / `*.e2e.ts` | e2e | real-browser Playwright (`site/` uses `*.spec.ts`; `admin/e2e/` uses `*.e2e.ts`) |
| `*.content.test.ts` | content | markdown/prompt-content assertions (commands, skills, agent prompts) — no I/O boundary, not one of the four canonical layers but a first-class fifth layer in this repo |

**CLAUDE.md deploy-model declaration:** root CLAUDE.md declares `## Deploy model` as **`direct`** — "ships via Helm chart + GHCR-pinned image tags, with no staging/production GitHub Environments and no deploy-staging→canary→promote-to-production pipeline." Unchanged since the last inventory (verified directly against `CLAUDE.md:111-113` at this commit). Per Step 5 of the SKILL, canary-eligibility tagging is skipped entirely for this repo (see Notes).

### 2. Service-boundary code

Every workspace has a Prisma-backed service layer (task-store: `task-service.ts`/`pull-request-service.ts`/`token-service.ts`; chat: `message-service.ts`/`thread-service.ts`/`token-service.ts`; admin: `agent-envs.ts`/`agent-cron-jobs.ts`/`agent-chat-tokens.ts`/`agent-work-queue.ts`/etc.) plus internal HTTP clients (`metrics/src/lib/task-store-client.ts`, `agent/src/shipwright-*-client.ts`, `admin/src/*-provisioning-client.ts`). The agent's `check-*.ts` / `loop-orchestrator.ts` family is a distinctive service-boundary cluster: it composes GitHub API reads with task-store writes and is the operational core of the dev-task/review/patch/deploy loop — ranked critical. This cycle's changes concentrate in **`agent/src/check-review.ts`**: a new `isBundleComplete` gate (skips a PR whose branch has an incomplete bundle-mate task, failing open — `.catch(() => true)` — on lookup error so a task-store hiccup never blocks review) and a **ref-backed `isAuthorAllowed` default** (previously a dev-tool-only override wired in from `scripts/hitl.ts`'s `SHIPWRIGHT_HITL_AUTHORS`; now defaults to reading `agentAuthorAllowlistRef` live, so a config-synced allowlist gates review candidacy in production, not just in the HITL dev tool — an empty allowlist still means unfiltered). `agent/src/index.ts` (composition entrypoint) now wires `agentAuthorAllowlistRef` into `syncConfig()`, giving it a config-sync-boundary role it didn't have before — stays category 2 (already an entrypoint/composition file), ranked critical since a wiring bug here would silently break the fail-open guarantee. `admin/src/agents.ts` absorbed the largest service-layer change: `AgentService.create()` now takes `typeName`/`repos`/`authorAllowlist`, and `AgentDetail` gained a derived `missingRequiredEnv: string[]` (required env keys from the type manifest with no corresponding `AgentEnv` row — informational only, not a create blocker or provisioning gate). New this cycle: `mcp-server/src/http-transport.ts` and `mcp-server/src/auth.ts` (unchanged since 2026-07-21, carried forward — no further changes this cycle).

### 3. HTTP routes / public API

Every service (metrics, admin, task-store, chat, mcp-server) exposes a Hono app factory with a route table documented in its own header comment. `admin/src/agents-api.ts`'s `POST /agents` create route gained real logic this cycle beyond pure composition: it now resolves the requested (or default `"coding"`) type to its manifest **before** creating any row (400s on an unknown type with zero rows written, rather than rolling back after the fact), then seeds `repos` as the union of the manifest's repos and any request-supplied repos, and wires `agentMemberService`/`agentTypeRegistry` into `AdminDeps`. This stays category 3 (still a route handler orchestrating calls to service/business logic beneath it) but the route now owns more of the create-time business decision than before — flagged for a Phase 3 reviewer to confirm the type-resolution-before-write ordering has direct smoke-layer coverage (a create-with-unknown-type 400 case), not just service-layer unit coverage. `admin/src/server.ts` remains a pure composition entrypoint. `agent/src/cron-handler.ts` and `agent/src/slack.ts` are treated as route-equivalent (own a wire contract with an external caller). Canonical layer is smoke throughout, consistent with the CLAUDE.md convention (`*.smoke.test.ts` — in-process `app.request()`).
