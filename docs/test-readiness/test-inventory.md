|---|---|---|
| `*.unit.test.ts` | unit | pure logic, no I/O |
| `*.integration.test.ts` | integration | real dependency behavior via recorded fixtures / injected doubles |

### 2. Service-boundary code

Every workspace has a Prisma-backed service layer (task-store: `task-service.ts`/`pull-request-service.ts`/`token-service.ts`; chat: `message-service.ts`/`thread-service.ts`/`token-service.ts`; admin: `agent-envs.ts`/`agent-cron-jobs.ts`/`agent-chat-tokens.ts`/`agent-work-queue.ts`/etc.) plus internal HTTP clients (`metrics/src/lib/task-store-client.ts`, `agent/src/shipwright-*-client.ts`, `admin/src/*-provisioning-client.ts`). The agent's `check-*.ts` / `loop-orchestrator.ts` family is a distinctive service-boundary cluster: it composes GitHub API reads with task-store writes and is the operational core of the dev-task/review/patch/deploy loop — ranked critical.

**2026-08-11 cycle — two independent claim-race closes and a reconciler scope reduction:**

1. **`task-store/src/pull-request-service.ts`'s `claim()` (CRF-1.1)** — moves its two conflict-detection conditions (modern same-phase guard, legacy review guard) from a pre-update JS `if` check against a `findUnique()` snapshot into the UPDATE statement's own `WHERE` clause via a negated `NOT: { OR: conflictConditions }`. Under the prior code, two concurrent claimers reading the same stale snapshot under READ COMMITTED could both pass the JS `if`, and the second writer would silently clobber the first's claim (a lost-update race). Now, Postgres — holding the row lock at execution time — is the sole arbiter: a losing writer's UPDATE matches 0 rows, Prisma throws `P2025`, and the catch block disambiguates `ConflictError` (row still exists, a concurrent claim now conflicts — the expected/desired outcome) from `NotFoundError` (row was deleted). `resetSkip()` also gained a companion UX fix: it now clears `blocked`/`blockedReason` in the same update, but only when the PR was auto-blocked by the skip-count mechanism specifically (`blockedReason` contains `"consecutive skips"`) — a block set by a different mechanism (e.g. the CI-failure-streak auto-block in `patch()`) is left untouched.
2. **`task-store/src/task-service.ts`'s `claim()`** — the same class of race is closed for tasks: the conditional UPDATE's `WHERE` clause gains an explicit `AND "claimedBy" IS NULL` (previously gated only on `status = 'pending'`).
3. **`agent/src/pr-state-reconciler.ts` — orphan-task reconciliation pass removed.** `listOrphanCandidateTasks`, `ghListOpenPrsForBranch`, and the `reconcileOrphanedTask`/`reconcileOrphanedTasks` functions are removed from both the `PrStateReconcilerDeps` interface and the reconciler body (a 547-line reduction in the paired unit-test file). The remaining `reconcilePrOpenTask`'s direct-path and branch-fallback heal logic, and their `startedAt`/BBR-1.1 headcount preconditions, are unchanged and re-documented in place to reflect that they're now the file's only two heal paths. This is a scope reduction to an already-inventoried, already-critical row — no new row, but a meaningful shrink of what this module's canonical-layer integration tests need to cover (a future Phase 3 migration pass should confirm the orphan-reconciliation-specific test cases were removed alongside the code, not left as dead assertions).
4. **`plugins/shipwright/scripts/compute-unaddressed-findings.ts` (PVD-1.1)** — extracted from `check-patch.ts`, new `hasUnaddressedFindings` implementation + its four helper functions (`isSelfCleanApprove`, `isAddressedByAuthorReply`, `isSupersededBySelfReview`, plus the new DRO-1.2 predicate) exposed for CLI use by both `check-patch.ts` (native candidate qualification) and `review.md` Step 9.5 (mechanical hard gate). Integration-layer half of the DRO-1.2 correction: the exclusion's effect on `hasUnaddressedFindings`'s overall boundary behavior (which reviews `check-patch.ts` treats as still-blocking when composing its candidate list, and which `review.md` Step 9.5 must also compute mechanically to decide verdict).

Companion, no-classification-impact changes: `chat/src/routes/messages.ts`, `task-store/src/routes/{tasks,prs}.ts` switch their local `readJson` duplicate to the new shared `lib/http.ts` import (see category 1); `agent/src/loop-orchestrator.ts` gained a header-comment-only note on `PR_REDISPATCH_COOLDOWN_MS`'s per-phase load-bearing status, no code change.

Earlier cycles' changes (HITL/blocked split, session-id threading, multi-repo/org filtering, CI-failure-streak auto-block, requested-reviewer inclusion, same-branch exclusivity guard, skip-reason taxonomy) are preserved in this file's git history — all were correctness/coverage fixes to already-inventoried, already-critical rows, no new category or layer introduced. `admin/src/agents.ts` / `agents-api.ts`, the K8s/manifest cluster, `agent/src/browser.ts`, and `scripts/minikube.ts` are unchanged since their respective introduction cycles.
