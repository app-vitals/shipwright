- **Package manager:** Bun workspaces (`bun.lock`), 8-workspace monorepo (`lib`, `plugins/shipwright`, `metrics`, `agent`, `admin`, `task-store`, `chat`, `mcp-server`) plus non-workspace supporting surfaces (`site/`, `brand/`, `scripts/`, `charts/` Helm chart, `demo/`, `.github/workflows/`)
- **Primary framework(s):** Hono (all HTTP services: metrics, admin, task-store, chat), Prisma + Postgres (admin, task-store, chat), Zod/`@hono/zod-openapi` for schema validation, Astro (site), Playwright (site + admin + metrics E2E, plus a new headless-Chromium agent runtime capability), Bun's built-in test runner throughout
- **Detected source roots:** `lib/`, `metrics/src/`, `agent/src/`, `agent/scripts/`, `admin/src/`, `task-store/src/`, `chat/src/`, `mcp-server/src/`, `plugins/shipwright/{commands,agents,skills,scripts,references}/`, `scripts/`, `brand/`, `site/src/`, `.github/workflows/lib/`

**CLAUDE.md layer-structure declaration:** the root CLAUDE.md's `## Test conventions` section declares five concrete layer names via filename suffix, used verbatim below instead of the rubric's generic unit/integration/smoke/E2E labels (unchanged since the 2026-07-21 inventory):

| Suffix | Layer | Covers |
|---|---|---|
| `*.unit.test.ts` | unit | pure logic, no I/O |
| `*.integration.test.ts` | integration | real dependency behavior via recorded fixtures / injected doubles |
| `*.smoke.test.ts` | smoke | HTTP route contracts — in-process `app.request()` (real `Bun.serve()` boot only when there's no Hono app-factory seam) |
| `*.spec.ts` / `*.e2e.ts` | e2e | real-browser Playwright (`site/` uses `*.spec.ts`; `admin/e2e/` uses `*.e2e.ts`) |
| `*.content.test.ts` | content | markdown/prompt-content assertions (commands, skills, agent prompts) — no I/O boundary, not one of the four canonical layers but a first-class fifth layer in this repo |

Not declared in CLAUDE.md but observed this cycle: `.github/workflows/test-*.sh` — plain-bash assertion scripts (no suffix convention, run via `bash <file>.sh` rather than `bun test`) covering CI workflow logic that lives outside the Bun test runner's reach entirely. Treated as a repo-specific sixth "shell" layer alongside the five above — see Notes and the new "CI shell scripts" entry in the Summary table.

**CLAUDE.md deploy-model declaration:** root CLAUDE.md declares `## Deploy model` as **`direct`** — "ships via Helm chart + GHCR-pinned image tags, with no staging/production GitHub Environments and no deploy-staging→canary→promote-to-production pipeline." ### 2. Service-boundary code

Every workspace has a Prisma-backed service layer (task-store: `task-service.ts`/`pull-request-service.ts`/`token-service.ts`; chat: `message-service.ts`/`thread-service.ts`/`token-service.ts`; admin: `agent-envs.ts`/`agent-cron-jobs.ts`/`agent-chat-tokens.ts`/`agent-work-queue.ts`/etc.) plus internal HTTP clients (`metrics/src/lib/task-store-client.ts`, `agent/src/shipwright-*-client.ts`, `admin/src/*-provisioning-client.ts`). The agent's `check-*.ts` / `loop-orchestrator.ts` family is a distinctive service-boundary cluster: it composes GitHub API reads with task-store writes and is the operational core of the dev-task/review/patch/deploy loop — ranked critical.

This cycle's changes concentrate in three places:

1. **`agent/src/claude.ts` (CSI-1.1/1.2) + its downstream consumers (`cron-handler.ts`, `loop-orchestrator.ts`, `cron-run-reporter.ts`, `admin/src/agent-cron-runs.ts`) (CSI-2.2/2.3)** — `createRunClaude`'s stream consumer now captures a Claude session id off the leading `system`/`init` line and surfaces it on every exit path (clean success, timeout, non-zero-exit failure). `cron-handler.ts` and `loop-orchestrator.ts` both thread that `sessionId` through every `completeRun()` call (success/silent/skip/failure), and the admin `PATCH` endpoint persists it on `AgentCronRun`. Purely additive plumbing of one new optional field through an already-integration-tested pipeline — no new module, no category/layer change to any file it touches. Ranked high: it closes a real operational gap (`investigate-cron`'s Step 1c previously had to fuzzy-match transcripts by mtime window; now it resolves the exact `.jsonl` file directly when `sessionId` is present).
2. **`task-store/src/pull-request-service.ts` / `task-service.ts` + new `task-store/src/lib/repo-org-filter.ts` (ORF-1.x)** — both services' `list()`/`distinct()` now accept `repo: string | string[]` and a new `org` filter, built via the shared `buildRepoOrgWhere` helper (`org` matches via `repo: { startsWith: "<org>/" }` since there's no dedicated org column). `admin/src/admin-ui.ts`/`admin-ui-pages.ts` grew a matching `org`/`repo` native multiselect on the Tasks/PRs filter forms (ORF-2.x), switching from `c.req.query()` (first-value-only) to `c.req.queries()` (all repeated values) to round-trip a multiselect submission correctly.
3. **`task-store/src/pull-request-service.ts`'s `patch()` (CSD-1.1)** — gained an optional `ciFailureSignature` param. A matching-signature streak increments `consecutiveCiFailureCount`; a differing/first-seen signature resets it to 1; crossing `CI_FAILURE_BLOCK_THRESHOLD` (3) on a matching increment also sets `hitl`+`blockedReason` in the same update call, mirroring `recordSkip()`'s existing auto-block pattern. `commands/patch.md`'s Step 6b computes the signature (sorted, comma-joined failing job names) and Step 6d.5 forwards it — this is the CI-fix loop's own spin-detection mechanism, distinct from `agent/src/loop-orchestrator.ts`'s `SPIN_DETECTION_THRESHOLD` (same constant value, different subsystem).

Also this cycle: **`agent/src/check-review.ts` (RRR-1.1)** — `getReviewCandidates` now also includes a self-authored PR if the agent's own GitHub identity is a requested reviewer on it (new `reviewRequests` field on `PrInfo`), layered strictly on top of the self-review exclusion — the author-allowlist exclusion still applies unconditionally, since `reviewRequests` can be set by any author with write access (including on their own PR) and isn't itself an access-control signal. A correctness/coverage fix to an existing service-boundary module, not a new category-2 surface.

`admin/src/agents.ts` / `agents-api.ts` and the K8s/manifest cluster are otherwise unchanged this cycle. `agent/src/browser.ts` and `agent/src/pr-state-reconciler.ts` (RDG-1.1) are unchanged since 2026-07-31/2026-07-30.
